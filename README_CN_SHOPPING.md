# 燕雲茶館｜商品前瞻論壇

商品圖鑑：https://ruanni-yanwu-teahouse.besideocean.chatgpt.site/products

工作流程每 3 小時自動執行，無須每次手動按 Run workflow；GitHub 排程可能略有延遲。新找到的陸服購物公告會自動整理進「全部商品」、公開於商品圖鑑，並在同一次掃描推播到指定 Discord 論壇，不必等管理者核稿。自動資料標示「自動整理・待核對」，你可以之後再修正。相同商品識別碼後續再次發布時，會在原貼文內追加新紀錄。國際服資料仍需管理者確認同款並補回原商品，沒有自動以名稱猜測或預測上線日。

## 第一次設定

1. 在 Discord 建立**論壇頻道**，建議名稱「🛍️｜商品前瞻」，預設版面選「圖片展示／圖庫」。
2. 在伺服器設定 → 整合 → Webhooks 建立新的 Webhook，指定上述論壇，複製 Webhook 網址。
3. 到本專案 Settings → Environments → discord-production → Add environment secret：
   - Name：`CN_SHOPPING_DISCORD_WEBHOOK_URLS`
   - Value：貼上論壇 Webhook 原始網址。
4. 不要修改原有 `OFFICIAL_DISCORD_WEBHOOK_URLS`；它繼續服務台港澳官網監控。新商品工作流程沒有回退到舊頻道的行為。
5. 第一次先不要設定「發文必須選標籤」。本版以「【商品類型】商品名稱」作標題，標籤可由管理者手動補上；尚未設定自動標籤 ID。
6. 等候自動掃描，或到 Actions → Scan WWM CN shopping → Run workflow → mode 選 scan，便會收錄商品並推播。

無須提供 Webhook 給聊天或寫進程式碼；只放在 GitHub Environment secret。可一行一個網址設定多個論壇（最多 10 個）。相同伺服器與論壇只投遞一次。網站帳號的私人收藏和備註不會送進 Discord。

尚未設定新密鑰時，收集與待整理功能照常運作，Discord 推播會顯示等待設定；不會誤送到舊頻道。原本已人工整理的商品不會整批重送；既有未修改的自動初稿會補公開並推播。

## 貼文內容

- 商品圖片、名稱、描述與官方原文；類型放在論壇標題。第一張卡片直接顯示陸服價格與上架日期，有國際服販售資料時也分開顯示國際服價格與上架日期。
- 商品不再另設「官方原文名稱」欄位，統一使用商品名稱。Discord 不顯示國際服查證說明、商品編號及推播編號；網站保留查證說明。已發出的舊訊息不會自動重寫，新發布與後續更新使用新版格式。
- 最新陸服／國際服販售紀錄分開顯示：原幣別價格、取得方式、上架日期、販售結束、用券條件、說明。上架日期取該筆販售開始日，未填則標示待確認，不以公告日期或通知日期代替；返場依各筆紀錄保留。
- 國際服查證狀態與依據；新增「尚未上架」，由管理者按資料確認日期標記。「待查證」不會自動改成「尚未上架」。已有國際服販售紀錄的商品應使用「曾於國際服上架」。
- 未知價格明列未確認，抽取成本不擅自估價。
- 有資料時附效果影片；分類包含「武學特效」「奇術特效」，不代表已有實際商品紀錄。
- 每次「發布並通知」保留當次商品快照，以後修訂不改掉已發布的歷史紀錄。

「一件商品一篇」依商品識別碼維持。補國際服資料請編輯原商品，不要建立另一個商品識別碼。原貼文遭刪除後，Discord 明確回報找不到原貼文（代碼 10003）時，會在同一論壇重新建立一篇，再把商品對應更新為新篇。原貼文鎖定、權限不足或一般連線錯誤時不會據此重建。

## 國際服上架後怎麼更新

1. 在「全部商品」找到原本的陸服商品，開啟「編輯商品」。
2. 按「新增國際服販售紀錄」，核對取得方式、貨幣、價格、上架／販售開始日期、優惠及本次國際服官方公告。不要覆寫原陸服紀錄。
3. 將國際服狀態設為「曾於國際服上架」，補上「國際服官方依據網址」與資料確認日期。僅預告時使用「官方已預告」，依公告填未來的販售開始日。
4. 保持勾選公開商品圖鑑，按「發布並通知 Discord」。下一次掃描會在該商品的原論壇貼文內追加兩服最新整理，原先的訊息仍保留；不是改寫首篇訊息。

「儲存，不通知」只更新網站；「加入比較」只供並排查看，不會發布、合併商品或建立論壇對應。國際服公告仍需人工確認同款並補回原商品，不會自動合併。

Discord 圖片提供大圖檢視；「商品圖鑑」連到本站該商品，查看完整兩服整理與歷次販售；各服「販售紀錄」標題則連到該筆官方公告，方便查證。

論壇內的資料可直接閱讀，網站用於管理、查證與多商品並排比較。本版尚未加入收藏按鈕、私人 `/想買清單`、自動國際服同款配對與上架提醒。成員可先自行對貼文加 🛍️ 表情，該反應是公開標記，並非私人購物清單。

## 排程與手動操作

Actions → Scan WWM CN shopping → Run workflow：

- `scan`：收集公告，投遞管理者已發布的商品。
- `preview`：只讀官網，不寫網站、不發 Discord。
- `recover_message_url`：平常留空；只在「Discord 已發送、回執未確認」時使用。

獨立 concurrency group；不修改兌換碼、YouTube、台港澳公告的去重資料。使用 GitHub OIDC 驗證指定儲存庫、分支、工作流程與 Environment，沒有另設長效網站同步密鑰。

## 傳送失敗與復原

Discord 與網站無法共用資料庫交易。程式在發送前會先留下傳送狀態；若收到連線中斷、5xx 或回執寫入失敗等不確定結果，下一次不會盲目重送或另建商品貼文。

若已看到正確的論壇訊息：

1. 在該訊息選「複製訊息連結」（不是只複製論壇貼文連結）。
2. 手動執行上述工作流程，mode 選 scan，`recover_message_url` 貼上訊息連結。
3. 程式會用同一 Webhook 讀回訊息，核對伺服器、訊息擁有者、當次商品快照的文字、價格、來源及整理時間後，補記回執；不會發新訊息。

若確認 Discord 根本沒收到，保留 GitHub 錯誤紀錄，請協助維護的人核對並解除該筆待確認傳送；不要任意改商品編號或刪資料表來繞過。

## 自動整理與發布

新商品公告會直接進入「全部商品」、公開於圖鑑並排入 Discord 發送佇列。商品與通知快照同時儲存；重複掃描不會重複發文。

- 同一篇公告有多個明確商品時分件建立；純玩法公告不會被當成商品。
- 自動擷取名稱、分類、明確價格、原幣別、販售日期、優惠與可配對的官方圖片；不明欄位留空或標示待確認。
- 圖片無法配對時，可先發布文字資料與官方來源，不會拿不相干的圖片補上。
- 無法拆分的購物公告以「待拆分」項目公開，保留官方公告，之後可手動拆成商品。
- 自動發布日期與人工確認日期分開；不會把掃描日期當成人工核稿日期。
- 已有、未修改的自動初稿會補公開並推播。你已修改、隱藏或標記暫不收錄／已處理的資料，不會被自動覆寫或重新公開。
- 已有同名商品保留原紀錄，不擅自用新公告覆寫舊價格。

有空時登入管理者帳號，在「全部商品」選「自動整理・待核對」，按「核對資料」即可修正。完成核對後可填資料確認日期；只修正部分欄位也可以先儲存。按「儲存，不通知」只更新網站；按「發布並通知 Discord」會在原商品論壇貼文追加修正版。

## 上架優惠怎麼填

在商品編輯的每筆「取得方式與販售紀錄」中：

| 欄位 | 用途 |
| --- | --- |
| 原價／一般售價 | 沒有上架折扣時的價格，未確認可留空。 |
| 上架優惠價 | 上架期間的特價，與原價使用同一貨幣。 |
| 優惠開始／優惠結束日期 | 可單獨記錄日期；未公布結束日可留空。 |
| 優惠開始／優惠結束時間 | 選填，依台灣時間記錄，支援精確到秒。 |
| 優惠說明 | 例如首發期間限定、購買限制等。 |
| 用券條件 | 折音券、惠音券的使用或不可疊加限制。 |

新發布及後續更新的 Discord 訊息直接顯示商品卡片，不再附開頭介紹文字或重複的分類欄位。卡片同時列原價、上架優惠價、優惠期間及用券條件。網站會標記優惠期間內、尚未開始、已結束或期間待確認；過期優惠不當作目前的排序價格。

公告中明列原價和優惠價時，新商品初稿也會分開擷取；已有手動紀錄不覆寫。

上架／販售開始與販售結束也分成日期、時間兩欄。只填日期會保存原日期，不自動補成午夜；只有明確填入時間才記錄時分秒，既有精確時間繼續保留。

若更新舊貼文時 Discord 回應 HTTP 400／404 且代碼為 10003，系統會保留同一筆傳送狀態，只解除該商品、該論壇的舊貼文對應，重新建立一篇並記錄新連結。其他論壇與商品不受影響。若新貼文傳送結果不確定，會停止重試，仍可用原有訊息復原流程補回執，避免重複開篇。錯誤紀錄只列服務名稱、API 代碼與欄位代碼，不輸出 Webhook 或原始回應內容。


## 原貼文刪除後重新發布

1. 到網站開啟原商品，核對資料後按「發布並通知 Discord」，不必重新新增商品。
2. 等待下一次自動掃描；要立即處理可手動執行 `Scan WWM CN shopping`。已有待發更新時，不必重複按發布。
3. 系統先嘗試原篇；收到明確的找不到原貼文回應後，在同一論壇建立新篇，之後所有更新沿用新篇。

網站內的商品、兩服販售紀錄與已發布快照會保留。Discord 已刪除的原貼文與成員留言無法由此還原。
