# 燕雲茶館｜商品前瞻論壇

商品圖鑑：https://ruanni-yanwu-teahouse.besideocean.chatgpt.site/products

工作流程每 15 分鐘巡查兩服最新兩頁公告（每小時第 08、23、38、53 分），另於每天台灣時間 05:07 完整補查兩服近 90 天（UTC 21:07）。GitHub 排程可能延後，時間為預定啟動時間。新公告會初步整理成商品、公開於網站，並在同一次掃描推播到 Discord 論壇。重複掃描不重複建立商品；人工修改、隱藏或刪除的商品不會被重新公開。純功能更新不當作新販售商品。

## 收集與保留範圍

同時掃描陸服與台港澳國際服官網；快速巡查只讀最新兩頁，每日補查才逐頁讀取近 90 個台灣曆日（含今天）的商品相關公告；依發布日期判斷，不依抓取時間。純平衡、修復、玩法文章不收錄，綜合更新中含商品上架資訊則保留。

同名商品以繁簡轉換與標點正規化後合併，另一服及返場紀錄依「伺服器＋官方公告來源」去重追加，不覆寫原有名稱、圖片、人工備註及舊販售紀錄。名稱不同時不猜測為同款，需由管理者核對。

90 天只限制待整理公告；已整理公告、商品、私人紀錄及歷次販售資料不會因時間到期刪除。官網解析失敗會回報錯誤，不會清空舊資料。大量公告分批同步，沿用既有的商品首篇更新與讀回核對流程。

## 論壇設定

1. 在 Discord 建立論壇頻道，預設版面可選圖庫。
2. 為此論壇建立 Webhook。
3. 到 GitHub Settings → Environments → discord-production，設定 `CN_SHOPPING_DISCORD_WEBHOOK_URLS`。多個論壇以換行分開，最多 10 個。
4. 保留台港澳公告使用的 `OFFICIAL_DISCORD_WEBHOOK_URLS`；商品監控不會使用該密鑰。
5. 商品類型標籤使用「套裝、髮型、武器外觀、伙伴配飾、武學特效、奇術特效、坐騎、資源禮包、其他」。建立後，將各標籤 ID 依論壇頻道 ID 填入 `discord-product-tags.json` 的 `channels`。所有 ID 都是公開識別碼，不是權杖。綁定完成前不啟用發文必選標籤。

新商品會依網站分類帶入一個標籤；一般「特效」或其他未列類型歸「其他」。既有商品首篇更新保留原論壇標籤，不會清空自選標籤。Webhook 無法建立論壇標籤或修改既有貼文的標籤，這兩項需在 Discord 管理端完成；未完成綁定時，日誌明示尚未啟用，不宣稱已套用標籤。

Webhook 只放 GitHub secret，不放網站或程式碼。網站私人收藏與購物筆記不會送到 Discord。

## 貼文內容

陸服與國際服各顯示一張最新商品資訊卡，格式與「玄瑛·羅浮春華」一致：原價／一般售價、取得方式、上架日期、上架優惠價，以及「更多商品詳情」超連結。有幾服的紀錄就顯示幾張卡，不增加空白的另一服。

Discord 不顯示販售結束、上架優惠期間、依據公告、備註、商品備註或優惠說明，也不帶入販售備註、用券補充文字與優惠備註。原始資料仍留在網站。新貼文與既有首篇更新共用相同格式；每次更新後讀回 Discord 核對成功，才記錄完成。未知價格不估算。只有影片的商品附官方影片連結，不拿其他商品的圖片代替。

網站能直接播放受支援的官方 MP4／WebM，其他 HTTPS 影片仍提供開啟連結。官方圖片以不傳送來源網址的方式讀取，避免來源網站的防盜連限制。

## 編輯與兩服比對

在原商品按「編輯」，新增國際服販售紀錄，填取得方式、價格、貨幣、上架日期及該筆國際服官方公告，將狀態設為「曾於國際服上架」。按「發布並通知 Discord」後，下次掃描會更新原論壇首篇。保留陸服與先前檔期的紀錄；「加入比較」只供並排查看。

取得方式包含商店直購、和鳴商店、玉振揚音、聞音商店、商店兌換、轉盤獎池、活動兌換、戰令及其他。貨幣可自由輸入，也提供長鳴珠、長鳴玉、音玉、八音竅建議。

商品與每筆販售紀錄的備註仍可在網站自由填寫，但不發布至 Discord。舊資料中有意義的用券條件保留於網站販售備註。必填欄位以紅色「＊」顯示。

上架優惠價與原價分開記錄。日期可單獨保存，時間選填；未填時間不補成午夜。未公布的結束日留空。網站保留優惠歷史並標示期間狀態，不把過期優惠當成目前價格。

## 刪除、還原與重發

在商品編輯視窗按「刪除商品」，確認後即從公開頁撤下，取消尚未發送的通知，並防止再次掃描自動加入。管理者可從「已刪除」篩選還原為未發布草稿；私人購物筆記與歷史資料保留。Discord 已發出的貼文請另外手動刪除。

原 Discord 貼文遭刪除時，在原商品按「發布並通知 Discord」。系統收到明確的找不到貼文回應（Discord 10003）後，重新建立一篇並沿用新連結。權限、鎖定或連線錯誤不會盲目另開篇。

`shopping-maintenance.json` 提供一次性的刪除、重新發布及首篇格式更新。每個 requestId 只處理一次；重跑不會重複推播，也不會刪掉之後手動還原的商品。`refresh_all` 只更新已有論壇對應的公開商品首篇，保留成員留言；原篇不存在時重建。

## 排程與復原

Actions → Scan WWM CN shopping → Run workflow：

- `scan`：收集、同步商品並發送通知。
- `preview`：唯讀官網預覽，不寫網站或 Discord。
- `recover_message_url`：Discord 已發送但回執未確認時，貼完整訊息連結以核對並補記回執，不重送。

GitHub OIDC 僅接受指定儲存庫、main 分支、工作流程及 discord-production。沒有長效網站同步密鑰。遇到 5xx、連線中斷或回執失敗等不確定結果時保留傳送狀態，避免重複開篇。

## 對應武器、武學與奇術

商品可選填 `baseName`：武器外觀顯示「對應武器」、武學特效顯示「對應武學」、奇術特效顯示「對應奇術」。編輯器依相同商品類型的既有名稱提供可輸入選單。商品詳情、卡片、比較、搜尋篩選及新 Discord 首篇格式均使用此欄位；留空時不顯示，也不要求猜填。

公告需明確把基礎名稱與該商品連在一起才會自動填入；多種不同對應、其他商品段落或無明確名稱一律留空。自動補充只填未經人工整理且原欄位空白的商品，保留手動值與原介紹。
